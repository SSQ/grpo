# ARCHITECTURE

## 1. 目标与约束

在**单张 8GB 消费级显卡**上完成一次可复现的 GRPO 强化学习实验，回答三个问题：

1. 规则奖励（可验证奖励，RLVR）在 0.5B 小模型上能否稳定驱动行为改变？
2. 训练集难度该如何选，才能让 GRPO 真正产生梯度？
3. 全量微调与 LoRA 在该场景下的成本/效果如何权衡？

选择算术题作为任务，是因为奖励可被程序精确判定（零噪声、零标注成本），
且难度可以通过位数连续调节，便于把基线调到"可学习区间"。
任务类型与 DeepSeek-R1 / TinyZero 等可验证奖励 RL 工作一致。

## 2. 流水线

```
probe_baseline.py            train_grpo.py              probe_baseline.py           compare_results.py
基线探测（定难度区间）  →   GRPO 训练 200 步       →   同评估集复测（seed=42） →    对比表 + 样例 + 曲线
6 难度 × 50 题               1000 条程序化训练集          --model outputs/grpo_ckpt
greedy + 8 采样              每步 4 prompt × 8 采样
      ↓                            ↓                            ↓                           ↓
outputs/baseline_probe.json  outputs/grpo_ckpt/          outputs/post_train_probe.json  outputs/figures/
                             outputs/train_log.json                                     train_curves.png
```

关键约束：基线与训练后评估必须使用相同 `seed=42` 与相同题量，保证题目集合一致，
否则提升中会混入题目难度差异。

## 3. GRPO 配置与选型理由

配置位于 `src/train_grpo.py` 的 `GRPOConfig`：

| 配置项 | 取值 | 选型理由 |
|--------|------|---------|
| `num_generations` | 8 | 组内采样数 K：K 越大 advantage 估计越稳但生成越慢；8 与基线 `pass@8` 口径一致 |
| `beta` | 0.0 | KL 系数为 0，不加载参考模型，省约一份模型显存；短训练（200 步）不需要防漂移 |
| `epsilon` | 0.2 | PPO-clip 裁剪范围，通用默认值 |
| `temperature` | 1.0 | 保证组内多样性——组内奖励方差是 GRPO 唯一的梯度来源 |
| `max_completion_length` | 64 | 答案仅需几个 token，64 足以容纳 `<answer>` 标签与偶发多余输出 |
| 学习率 | 2e-6（全量）/ 2e-4（LoRA） | 全量微调用小步长；LoRA 可训练参数少，需要高 100× 的等效步长 |
| 批次 | `per_device_train_batch_size=8` × `gradient_accumulation_steps=4` | 每步 = 4 个 prompt × 8 条采样 = 32 条 completion |
| `bf16` | True | 显式 `model_init_kwargs={"torch_dtype": "bfloat16"}`，规避 fp16 数值下溢（见 §7） |
| `gradient_checkpointing` | False | transformers 5.x 下与 `generate` 冲突（见 §7），0.5B 模型显存足够 |

训练集由 `build_dataset` 程序化生成，配比在 `LEVEL_MIX` 中定义：
L3 三位数加减 50%、L5 两位×一位 25%、L2 两位数加减 25%。

## 4. 复合奖励设计

两个独立 reward function，由 TRL 分别记录曲线并求和：

```python
reward = reward_correct(1.0 正确 / 0.0 错误)      # 宽松解析：有标签取标签内数字，否则取最后一个数字
       + reward_format(0.2 符合 <answer>N</answer>)  # 与正确性解耦的格式分
```

两个取舍：

- **正确分用宽松解析**：基线模型几乎不输出标签（格式率 0.00~0.08），若严格要求标签内数字，
  正确信号同样为 0，组内奖励方差为 0 → advantage 全 0 → 训练无法启动。宽松解析保证冷启动有梯度。
- **格式分权重 0.2**：有意低于正确分，形成"主信号 + 辅助信号"的层级。训练日志显示格式分均值
  在 200 步内从 0.015 升到 0.181（对应约 0.20 的满分），爬升明显慢于正确分——组内归一化后，
  0.2 的增量被正确性（0/1）的方差稀释，这是 reward shaping 权重设计的直接体现。

## 5. 难度选题依据（本项目的方法论核心）

GRPO 的 advantage 来自**组内奖励方差**：同一 prompt 采样 K 条，若全对或全错，
`r - mean` 为 0，该组不产生梯度。因此选题的核心指标是
**informative group rate**（组内 0 < 正确数 < K 的比例）。

基线探测实测（50 题/难度，K=8，T=1.0，宽松口径）：

| 难度 | greedy 正确率 | 采样平均正确率 | pass@8 | informative group rate | 用途 |
|------|:---:|:---:|:---:|:---:|---|
| L1 个位数加法 | 0.98 | 0.85 | 1.00 | 0.50 | 留作泛化评估 |
| L2 两位数加减 | 0.76 | 0.65 | 0.90 | 0.70 | 保底，占训练集 25% |
| L3 三位数加减 | 0.42 | 0.37 | 0.84 | 0.80 | 主训，占 50% |
| L4 表内乘法 | 0.62 | 0.60 | 0.96 | 0.68 | 留作泛化评估 |
| L5 两位×一位 | 0.20 | 0.22 | 0.62 | 0.62 | 主训，占 25% |
| L6 两位×两位 | 0.08 | 0.04 | 0.18 | 0.18 | 不进训练集（近乎全错，无梯度） |

L1 太易（组内常全对）、L6 太难（组内常全错），二者的 informative 比例分别处于两端；
L3 的 0.80 最高，作为主训难度。L1/L4/L6 完全不进训练集，用于回答
"未参与训练的难度会不会也提升"。

## 6. 结果分析

### 6.1 训练前后对比（`outputs/*.json`）

| 难度 | 在训练集 | 格式率 基线→全量→LoRA | greedy 正确 基线→全量→LoRA | pass@8 基线→全量→LoRA |
|------|:---:|---|---|---|
| L1 | — | 0.00 → 0.96 → 1.00 | 0.98 → 1.00 → 1.00 | 1.00 → 1.00 → 1.00 |
| L2 | √ | 0.02 → 1.00 → 1.00 | 0.76 → 0.98 → 1.00 | 0.90 → 1.00 → 1.00 |
| L3 | √ | 0.06 → 0.96 → 1.00 | 0.42 → 0.88 → 0.90 | 0.84 → 0.98 → 0.96 |
| L4 | — | 0.00 → 0.84 → 1.00 | 0.62 → 1.00 → 1.00 | 0.96 → 1.00 → 1.00 |
| L5 | √ | 0.00 → 0.98 → 1.00 | 0.20 → 0.88 → 0.96 | 0.62 → 0.94 → 0.98 |
| L6 | — | 0.08 → 0.98 → 1.00 | 0.08 → 0.22 → 0.24 | 0.18 → 0.42 → 0.38 |

四点观察：

1. **格式是表层行为，RL 极易学会且完全泛化**：包括从未训练的难度，格式率全部达到 0.84 以上，
   LoRA 全部为 1.00。
2. **训练集内能力显著提升**：L5 从 0.20 → 0.88（4.4×），L3 从 0.42 → 0.88。
3. **未训练难度同样提升**：L4 0.62 → 1.00，说明不是记住了题目，而是强化了"做对算术"的内部回路。
4. **超出能力边界的难度几乎不涨**：L6 仅 0.08 → 0.22（LoRA 0.24），pass@8 0.18 → 0.42/0.38。
   RL 是在模型已有能力边界内重排概率分布，不会凭空创造能力。

样例对照（greedy 解码，基线 → 全量）：

| 题目 | 基线输出 | 训练后输出 |
|------|---------|-----------|
| 902 - 848 = 54 | `174` | `<answer>54</answer>` |
| 403 - 322 = 81 | `181` | `<answer>81</answer>` |
| 28 × 8 = 224 | `112` | `<answer>224</answer>` |
| 98 × 3 = 294 | `194` | `<answer>294</answer>` |
| 23 × 9 = 207 | `871` | `<answer>197</answer>`（仍错） |

### 6.2 训练曲线（`outputs/figures/train_curves.png`）

| 指标 | 全量（首→末） | LoRA（首→末） |
|------|:---:|:---:|
| `rewards/reward_correct/mean` | 0.475 → 0.894 | 0.644 → 0.950 |
| `rewards/reward_format/mean` | 0.015 → 0.181 | 0.020 → 0.200 |
| `entropy` | 0.579 → 0.081 | 0.407 → 0.011 |
| `frac_reward_zero_std` | 0.05 → 峰值 0.60（第 30 步）→ 0.25 | 0.15 → 峰值 1.00（第 85 步）→ 0.85 |
| `grad_norm` 最大值 | 50.0 | 1.63 |
| `train_loss` | -0.112 | -0.004 |

- 正确分在前 20 步从 0.475 升到 0.88 附近，之后在 0.78~0.89 区间震荡：格式与简单题先收敛。
- 格式分缓慢爬升，0.181 的均值对应约 90% 采样带格式（满分 0.2/条），
  其"慢"主要来自组内归一化下的信号稀释，而非学不会。
- `frac_reward_zero_std`（退化组比例）先升后降：简单题迅速饱和为全对，模型变强后
  中等难度从"全错"转为"有对有错"，该曲线是 GRPO 有效训练率的直接读数。
- 策略熵大幅下降，说明策略在目标任务上收敛为接近确定性的输出分布。

### 6.3 全量微调 vs LoRA

| 维度 | 全量微调 | LoRA (r=16, q/k/v/o_proj) |
|------|:---:|:---:|
| 训练耗时（200 步） | 617.9 s | 607.2 s |
| GPU 峰值显存 | 5.46 GB | **3.36 GB** |
| 学习率 | 2e-6 | 2e-4 |
| L5 正确率 / pass@8 | 0.88 / 0.94 | **0.96 / 0.98** |
| L3 正确率 | 0.88 | **0.90** |
| L6 正确率 | 0.22 | **0.24** |
| 格式率 | 0.84~0.98 | **1.00（全部难度）** |
| 末态熵 | 0.081 | 0.011 |

LoRA 在本场景显存降低约 38%，耗时相当，正确率与格式遵循整体略优。两个原因：

1. **正则化效应**：只更新 adapter，参数空间受限；全量 bf16 在短训练中更易受单步梯度噪声影响
   （`grad_norm` 多次达到 10~50，LoRA 全程不超过 1.63）。
2. **学习率等效**：LoRA 用 2e-4（全量的 100×），单步移动量更大，短训练收敛更快。

代价是**探索更早枯竭**：LoRA 末态熵 0.011（全量 0.081），后期 `frac_reward_zero_std`
高达 0.85，多数组已全对或全错，梯度信号变稀。本任务 200 步即到顶，未暴露该问题；
更长训练或更难任务需要配熵正则、提高温度或加 KL 约束。

## 7. 工程问题与定位过程

| 问题 | 根因 | 解法 |
|------|------|------|
| `from trl import GRPOTrainer` 触发 `import vllm` 失败 | trl 0.21 调用 transformers 私有函数 `_is_package_available()`；transformers 5.x 将其返回值由 bool 改为 `(bool, version)` 元组，非空元组恒为真，导致所有可选依赖被误判为已安装 | `src/trl_compat.py` 在导入 trl 前把返回元组的 `is_*_available()` 补丁为真实布尔 |
| `'Qwen2ForCausalLM' object has no attribute 'warnings_issued'` | transformers 5.x 移除了 4.x 的警告去重字典，trl 0.21 初始化时仍读写该属性 | 补丁为 `PreTrainedModel` 增加类级空字典 |
| 训练时采样补全为乱码、奖励恒为 0 | transformers 5.x 下 `gradient checkpointing` + train 模式会使 `generate` 前向输出损坏（同权重 eval 模式输出正常） | 关闭 `gradient_checkpointing`；显存不足改用 `--lora` |
| 一步训练后全部权重 NaN/Inf | 基座 `config.json` 标注 `torch_dtype=float16`，不显式指定会按 fp16 加载；AdamW 的 `eps=1e-8` 在 fp16 下下溢为 0，导致 0/0=NaN、m/ε=Inf | 显式 `model_init_kwargs={"torch_dtype": "bfloat16"}`。定位方法：逐微批确认 loss/梯度有限 → 拦截 clip 与 `optimizer.step` → 发现 step 前正常、step 后全毁 → 检查 dtype |
| 生成时提示 `top_k not valid` | 模型自带 `generation_config.json` 含 top_k，与显式 `do_sample` 冲突 | 无害警告，忽略 |

## 8. 模块职责

| 文件 | 职责 |
|------|------|
| `src/probe_baseline.py` | 题目生成、greedy 与 K 采样解码、格式/严格/宽松三种口径判定、informative group rate 统计；同时承担训练后评估（自动识别 LoRA adapter） |

## 9. 局限与可扩展方向

- 单次运行、单卡、单模型规模（0.5B），结论的普适性需要在更大模型与真实推理任务上复核。
- 评估题量 50/难度，正确率的分辨率为 0.02，数个百分点内的差异不宜过度解读。
- `beta=0` 无 KL 约束，长训练存在策略漂移风险；扩到长训练时应恢复参考模型。
- 可扩展实验：调整格式分权重（0.2 → 1.0）观察信号竞争；移除格式分验证"RL 只强化被奖励的行为"；
  改变 K（4 / 8 / 16）观察 advantage 估计质量；把 L6 纳入训练集观察 informative rate 塌陷后的效率损失。
